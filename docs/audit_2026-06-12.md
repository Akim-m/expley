# Code + methodology audit (2026-06-12)

Two parallel audits (edge-case code audit; statistical methodology audit) run against
the post-landmark-feature codebase and the real artifacts. Code edge cases in the new
landmark module were fixed the same day; the statistical findings below are the
**next implementation wave** — several change the headline numbers and the population
they describe.

## Fixed same-day (landmark module edge cases)

- `*_lag_days` sentinel `-1.0` collided with real pre-publication tooling lags (a PoC
  one day before publication also produced -1.0, deeper pre-pub lags were *more
  extreme* than the "missing" sentinel — non-monotone). Now fills with `L+1` (later
  than any attainable in-window lag); negative lags preserved as real signal.
- Duplicate `cve_id` corpus rows silently multiplied counts through the non-unique
  index join, then crashed `.map()` with `InvalidIndexError`. Now raises a clear
  `ValueError` up front (`_published_series`).
- NaT `published` silently zeroed all landmark features. Now raises (mirrors
  `labels._validated_base`).
- `restart_clock` accepted negative landmarks, fabricating positive durations from
  negative ones. Now raises.
- `train --landmark` accepted a stale `landmark_features_{L}d.parquet` from an older
  build (NaN after merge → lifelines crash, but **xgb silently trained on it**). Now
  validates full coverage post-merge and tells the user to rebuild.
- Calibration plot titles are annotated `(post-landmark L=Nd)` — horizons after
  `restart_clock` are landmark-relative and the old labels were misleading next to
  non-landmark reports.

## P0 — statistical findings that materially distort reported numbers (open)

1. **Same-day events are silently deleted.** `prepare_modeling_frame` keeps
   `duration_days > 0`; durations are floored whole days, so an event hours after
   publication is duration 0 and dropped. Measured: **18,523 of 165,476 first-weap
   events (11%)**; for in-wild, negative+zero rows are **~26% of the 1,543 events** —
   precisely the exploited-at/before-publication stratum. Every short-horizon metric
   describes a "survived day 0" population without saying so. Fix: half-day convention
   (`max(delta, 0.5)`) or fractional-day durations in the label builders; report
   dropped-event counts in `metrics.json`; document.
2. **Events after the snapshot are kept as events** (2,043 first-weap events dated past
   2026-03-14; max 2026-05-23) — asymmetric observation windows, and the reason
   `c_index_tau` is 855 when the test design maxes at ~804. Fix: censor
   `event_date > snapshot` at the snapshot in `build_first_weaponization_labels`.
3. **No uncertainty anywhere.** In-wild test has ~191–224 events → c-index 0.837 has
   95% CI ≈ [0.79, 0.89]; the cox-vs-xgb gap (0.013) is ~half a standard error —
   model ranking on in-wild is unresolved. Fix: bootstrap CI inside
   `evaluate_survival` (resample precomputed risk scores, no refit; stratify on
   `event_observed`; shared indices for paired model deltas).

## P1 — estimator validity (open)

4. **The "IPCW" c-index degenerates to Harrell's C here.** Censoring is administrative
   (`C = snapshot − published`), so the train-side censoring KM is ≡1 over the
   comparable range — weights are all 1 — and the estimator's independence assumption
   is structurally violated (C is deterministic in `published`, which is a feature;
   train/test censoring distributions are disjoint). Fix: per-horizon cumulative/
   dynamic AUC on the fully-observed subcohort `published ≤ snapshot − h` (censoring-
   free by construction, ~15 lines), or exact truncated c-index using the *known*
   per-row censoring times.
5. **Calibration bins are meaningless on in-wild** (bottom six deciles hold 0–12
   events) and reveal ~10× probability compression at the top decile that the report
   doesn't surface; raw Brier ≈ null-model Brier to 3–4 decimals. Fix:
   `min_events_per_bin` (merge adjacent bins), Greenwood CIs per bin, and report
   IPA / scaled Brier (`1 − Brier/Brier_null`).
6. **lifelines' ridge scales with n, not events** (`n · penalizer · ||β||²/2`): with
   975 in-wild train events vs 234k rows, `penalizer=0.1` is ~24× the information
   scale — the direct cause of the compressed calibration slope. Fix: scale the
   penalizer by event rate (or CV); extend `fit_cox`'s `stable()` to require ≥5
   positives *among events*. Case-control subsampling of censored rows is a cheap
   complement (~50× faster fits, same estimates).
7. **KEV backfill contaminates the in-wild clock.** 246/975 (25%) of in-wild train
   events are dated exactly 2021-11-03 (catalog launch), with batch spikes after;
   only 1 event predates it. Durations for pre-2021 CVEs measure "when CISA launched
   a program". Fix: restrict in-wild training to `published ≥ 2021-11-03` (test is
   post-2024, unaffected) or left-truncate at `max(published, 2021-11-03)`; flag or
   drop the backfill-dated events.

## P2 — framing notes (document, don't re-engineer)

- **Landmark in-wild predicts time-to-KEV-listing**, partly CISA's detection lag:
  EPSS-at-landmark can already encode public exploitation that precedes KEV addition.
  Say so wherever landmark results are reported.
- **Cure fraction**: most CVEs will never enter KEV; long-horizon probabilities from
  Cox/KM are conceptually "not yet" — fine for ranking, misleading as absolute
  long-horizon risk. Note in methodology doc; a mixture-cure model is the honest
  formulation if long horizons ever matter.
- `cox_ph_assumptions`' 50k row subsample holds ~200 in-wild events — underpowered
  exactly where violations are likely. Sample all events + censored subsample.
- Transition models report a train-set c-index in the same field when test has no
  events (`c_index_on` distinguishes) — consider `null` instead.

## Sequencing recommendation

P0.1 + P0.2 first (label builders; they change every downstream number once, so do
them before further model comparisons), then P0.3 (CIs; cheap, makes all subsequent
comparisons honest), then P1.6 (penalizer) + P1.5 (calibration guards), then P1.4
(horizon AUC), then P1.7 (KEV clock).
